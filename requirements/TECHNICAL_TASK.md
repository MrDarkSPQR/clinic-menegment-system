# Технічне завдання (ТЗ)

## Назва проєкту: Clinic Management System

### 1. Загальний опис системи
Проєкт розробляється як клієнт-серверна система для автоматизації 
обліку пацієнтів та онлайн-запису в локальних медичних кабінетах. 
Система має архітектуру з підтримкою автономної роботи (Offline-first).

Система складається з двох ізольованих додатків:
1. **Desktop App (Локальний клієнт):** Робоче вікно для персоналу клініки, 
   що працює з локальною БД. Забезпечує роботу за відсутності інтернету.
2. **Web App (Публічний сервер):** API-сервер та веб-сторінка 
   для пацієнтів для створення записів онлайн.

---

### 2. Обґрунтування стеку технологій

*   **Backend API (FastAPI):** Висока швидкість роботи 
    та автоматична генерація інтерактивної документації (Swagger), 
    що спрощує інтеграцію з фронтендом та десктопом.
*   **Frontend (React + TypeScript):** Сучасний стандарт розробки. 
    TypeScript забезпечує строгу типізацію даних, 
    що мінімізує помилки при передачі медичних карток.
*   **Транспорт даних (Axios):** Використовується на фронтенді 
    для надійного виконання HTTP-запитів до API сервера 
    та зручної обробки помилок мережі.
*   **Desktop GUI (PyQt6):** Найпотужніший фреймворк для Python-десктопу. 
    Забезпечує високу швидкість роботи інтерфейсу на локальних ПК 
    та має готові компоненти для таблиць та календарів.
*   **Бази даних (SQLAlchemy ORM):** Дозволяє використовувати 
    єдиний код моделей даних як для локальної SQLite (в автономному режимі), 
    так і для серверної PostgreSQL.
*   **Інфраструктура розгортання (Docker & Docker Compose):** Дозволяє 
    запустити всю серверну частину (API + PostgreSQL) однією командою, 
    гарантуючи однакову роботу коду як у VS Code, так і на сервері.

---

### 3. Функціональні вимоги (MVP)

#### 3.1. Керування базою пацієнтів (Десктоп)
*   Додавання картки пацієнта з полями: UUID, повне ім'я, номер телефону.
*   Перегляд списку зареєстрованих пацієнтів.
*   Зберігання історії прийомів із прив'язкою до ID пацієнта.

#### 3.2. Розклад та валідація візитів (Десктоп)
*   Створення запису на прийом: вибір пацієнта, лікаря, дати та часу.
*   Валідація конфліктів: система блокує збереження запису, 
    якщо на зазначений час у лікаря вже існує інший активний прийом.
*   Фільтрація та відображення розкладу лікаря на поточний день.

#### 3.3. Публічний онлайн-запис (Веб-сайт)
*   Форма збору заявок від пацієнтів: Ім'я, Телефон, Дата, Коментар.
*   Передача даних через REST API на сервер із присвоєнням статусу "Нова заявка".

#### 3.4. Синхронізація та автономність
*   Автономний режим: примусове збереження всіх локальних операцій 
    у локальний файл SQLite без звернення до мережі інтернет.
*   Модуль синхронізації: відправка локальних змін клієнта на сервер 
    та стягування нових онлайн-заявок із сервера в локальну базу даних.

---

### 4. Нефункціональні вимоги

#### 4.1. Вимоги до сумісності та розгортання
*   Локальний десктопний додаток має запускатися на ОС Windows 10/11 
    без встановлення додаткового системного середовища Python.
*   Серверна частина (FastAPI + PostgreSQL) має розгортатися 
    однією командою через Docker Compose.

#### 4.2. Надійність та цілісність даних
*   Локальна база даних повинна повністю міститися в одному файлі `.db` 
    (SQLite) для можливості ручного копіювання як резервної копії.
*   Усі таблиці повинні генеруватися через єдині описи моделей SQLAlchemy.

#### 4.3. Безпека та бізнес-логіка (Ліцензування)
*   Хешування паролів адміністраторів при збереженні в БД.
*   Модуль перевірки тріалу: десктопна програма блокує інтерфейс 
    користувача після 3 днів з моменту першого запуску, 
    якщо сервер не підтвердить активацію комерційної ліцензії.
